## Rendering review PNGs

Run `node render.mjs` in this directory for all six sheets, or pass slugs, e.g. `node render.mjs setup settings`. Each input is a sibling `<slug>.svg`. The renderer uses installed Chrome and Playwright Core (local package, Node lookup path or the bundled Codex runtime). Set `CHROME_BIN` to select a particular Chrome executable. The test environment used arm64 macOS 26.6.2, Node 24.18.0, Playwright Core 1.62.1 and Chrome 156.0.8078.76. Use matching versions for byte comparisons.

Each verified render produces `review/<slug>.png` and updates its entry in `review/manifest.json`. Entries carry pixel dimensions, loaded font families, Chrome version and SHA-256 hashes of both inputs and outputs. The manifest retains earlier renders when a subset is requested. An entry describes the last render of that slug. Compare its SVG hash with the current source when using an older PNG.

The renderer checks text against its enclosing SVG viewports after font loading. It accounts for the sheets’ intentionally cropped swipe rows, scroll lists and rectangular clip paths. Visible text extending more than half a CSS pixel beyond a boundary is recorded with its frame and excess in pixels. The PNG is retained for inspection and the command exits nonzero. Crowding between controls or labels inside a frame still needs visual review.
